## Scope and substantive code audit

1. **Bounded puzzle cache**: `SoloProgressRules.puzzle` reuses identical immutable generated boards by versioned puzzle ID (max six) rather than rebuilding expensive 20×20 placements after a word selection or hint. Core tests assert cache identity, distinct seed behavior and v1 replay.
2. **Move-mode pan and pinch**: Official Compose gesture API `detectTransformGestures` supports one-finger pan and two-finger pinch in Move, with a centroid-anchored `BoardViewportTransform.zoomedAt`; Find mode still handles line tracing and first/end taps separately. Pressing the percentage returns to **100% full-board fit**, with exact pan=0.
3. **Meaningful finished puzzle**: actual recorded count, elapsed time and Assisted/Unassisted hint steps; Review completed board ↔ Results, Home, Records, Play another (Solo). No fictional score, rewards, automatic hints or new content.
4. **Improved word list**: pinned remaining-target heading, selected Remaining filter, independent list scroll. Tap-to-reveal target locations is intentionally **not** a free hint.
5. **Found message**: brief ✓ word-found confirmation and progress, existing optional haptics/short click. Feedback toggles persist across Android sessions privately, not in immutable seeded-save schema.
6. **Save and app isolation**: English v1/v2 word library, original Daily generation and identity, `schema4` save content, package ID, approved portraits and independent GridMates: Sudoku project unchanged.
7. **Test modernization**: previously outdated ShellSmokeTest text assertions were corrected to current Home, Solo, Options and Collections. New Android tests cover result/review flow and persisted feedback, alongside existing seed, hint, Daily, identity and backup tests.

## Failures intentionally recorded (all resolved before verified checkpoint)

- Early B4 JVM tests caught small floating-point/negative-zero pan residues at 100% fit; exact zero-clamp implemented and regression tests retained.
- Android test runner's first execution failed because **legacy smoke assertions referenced removed prototype text**; updated to current interface.
- New feedback setters originally conflicted with Kotlin property-generated JVM setters; renamed to distinct `updateHapticsPreference`/`updateSoundPreference`.
- A new UI test imported `assertExists` as a nonexistent extension rather than using its existing member method; removed the imports.
- **Final source SHA `2f888a2...` passed BOTH pipelines**. Earlier failed runs are *not* considered QA passes.

## Limits of this green audit

The **17 Android tests ran on an emulator**, not the user's actual phone. The tests exercise app launch/current navigation, results/review, data persistence and preferences; they do **not** prove all gesture paths or visual layouts. There is no automatic screenshot-diff benchmark of the new pinch/found animation. These remain physical QA:

- [ ] 20×20 100%: confirm all 20 rows/letters and the rounded bottom border fit without crop.
- [ ] 15×15 Classic and 20×20 Extended: Move mode one-finger pan to four corners, **two-finger pinch**, fit-to-100% by tapping zoom percentage; Find mode still selects first/end and drags actual diagonals without phantom movement.
- [ ] Hints: 12×12=2, 15×15=3, 20×20=4 and Daily=2; verify count exhaustion after app restart.
- [ ] Finish Solo and Daily: correct result stats, Assisted marking, Review Board ↔ Results, another puzzle where relevant, and journal records.
- [ ] Word list stays usable on narrow portrait/landscape, 200% font and with “Remaining” filter; compare with v0.4.5 owner screenshots.
- [ ] Toggle haptics/sound, reopen, verify preference persists.
- [ ] On-device latency check before/after seed cache, long-word selection across zoom viewport and any crash or ANR.
- [ ] Stable QA/release signing still separately tracked as [issue #11](https://github.com/PlayerEden/GridMates-Word-Search/issues/11) for future nondisposable beta, but **not a blocker for disposable developer alpha QA**.
