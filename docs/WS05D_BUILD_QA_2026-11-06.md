## What is implemented

1. Host makes a tentative, single-guest offer without claiming the guest slot.
2. Guest validates puzzle and recent chat, synchronously saves its new random reconnect token, then acknowledges the exact room/token.
3. Host commits guest admission only after correct acknowledgment and sends Joined **before** exposing the connected socket to heartbeat/board traffic; guest waits for this final authoritative state before showing Connected.
4. Interrupted pre-admission offers release their slot; interrupted post-accept joins leave the guest with a locally stored reconnect credential.
5. Active nearby sockets, claims and ephemeral chat are held in a ViewModel, retaining room identity across normal Android Activity recreation; intentional Back to Play exits and closes the room.
6. LAN protocol is **v4**, with corresponding NSD advertisement filter. No backward pairing with older experimental WS-05A/B/C builds.
7. Solo/Daily save schema, deterministic word-search generation and all free cosmetic unlocks stay unchanged.

## Critical physical acceptance remains OPEN

The code and emulator test do **not** prove the real host/client behavior during arbitrary network packet loss. The owner will separately verify:

- Two actual Android phones can find and join open/protected same-Wi-Fi rooms; wrong PIN does not trap the room; host/invited partner remain correctly identified.
- Interruption at the first Welcome and after Accept: guest slot is not incorrectly consumed, matching token reconnect works and other guests cannot steal an admitted partner.
- Both orientations while hosting and joining preserve real sockets/claimed words/chat and remember the room name/code; screen lock/background/return do not silently corrupt game state.
- Chat acknowledgment/retry, recent host history, simultaneous word claims, board touch/zoom/Find/Move and color ownership work on two actual phone screens.
- B5 font rendering and 200% system text, manual entry/guest Wi-Fi fallback and actual in-place QA APK update/signing continuity.
- If Android kills the *process*, the host room will still end; no persistent hosting service or cloud recovery exists. Messages remain unencrypted on a trusted LAN.
