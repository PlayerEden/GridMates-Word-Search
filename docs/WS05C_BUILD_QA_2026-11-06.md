## Shipping boundaries / what is **not** proven

- A guest's outgoing chat now needs a host-confirmed matching request ID before it is labeled delivered. Retry reuses the original ID, and the host responds with its prior accepted receipt rather than duplicating it.
- A confirmed message found in recent chat history after reconnect clears the pending state. Pending text remains retryable on disconnect, while a locally unqueued draft remains visible.
- Local room discovery stops after successful guest join and reconnection is limited to the same reserved room; chat updates are host serialized. **LAN protocol v3** requires both devices to use compatible builds.
- **No physical two-phone test has been performed**: real NSD/Wi-Fi discovery, optional PIN, live chat latency, lost acknowledgment while switching Wi-Fi, host premature reservation, guest reconnect under Android 16, narrow-screen and huge-font touch/keyboard behavior, zoom/Find/Move alignment, and actual in-place APK upgrades remain open.
- **Known admission race:** first guest may be reserved by the host before its welcome/credential is fully confirmed; host may need to restart room if this handoff fails. Plan a two-way welcome acknowledgment/rollback or a carefully protected host recovery flow in WS-05D.
- **Known lifecycle limitation:** changing screen/rotation or killing the host activity may close the in-memory room; full process/configuration preservation is not promised. Physical owner acceptance remains the merge gate.
- Chat remains on **trusted Wi-Fi**, ephemeral, unencrypted and not a cloud chat service. No new monetization, new portrait packs or Versus game modes.
