## Book Factory production contract — scope of next code/art pass

**Shared geometry package (fixed across themes):** projected 3D front silhouette; separate spine geometry; page-block edging; top/bottom/end line treatment; edge/contact lighting; binding bands; cover title ribbon and lower-theme plaque safe regions; actual depth and baseline guides; alpha silhouette templates; asset coordinates and exported DP targets. Prefer one repeatable master, not isolated AI renders with differing perspective. Allow a small curated book height/width class *at library layout stage* via coherent geometry variants, never random bitmap distortion.

**Each themed volume must include:** stable book/content ID, illustration master, cover overlay/export, spine motif/export, optional combined shelf render, small preview/thumbnail, theme plaque/icon and a manifest mapping all to common base geometry. Add metadata for chapter/page artwork only as used; do not generate gratuitous filler assets.

**Blank volume types:** neutral coming-soon, mystery future theme, and alternative quiet binding. They are visual placeholders only: no fake puzzle pages, unlocked book IDs, saved progress, achievements or a misleading Play action. Consider accessible description and honest "More books coming" copy in native UI.

**QA gates:** compare at 1:1 pixel and real phone dp against cream and dark matte; no 1–2px white seam, halos, jumbled letters, registered symbols, changed baseline or width. Confirm tap targets unaffected and center/neighbor cover rest on approved shelf. Version V2 files without overwriting V1; pin original and export SHA-256; import QA-only, run Android and independent art/release-isolation workflows, provide exact run numbers, direct GitHub artifact. Require owner phone acceptance before promotion.

## Workflow discipline

1. **One meaningful milestone per PR/checkpoint**, source-tested on development branch; append who/what/why/source SHA/QA/APK/rollback/next to journal after actual work. Don't repeatedly promise a future APK without building it.
2. Maintain **P0/P1 separation**: appearance improvements that affect readability or truthfulness (fringes, ®, game title) take priority; purely optional animations, extra decoration and aesthetic shelf tweaks do not.
3. Hardware QA **can happen concurrently** while asset production runs. Track failing modes and exact reproduction steps; never infer 2-phone play from code tests.
4. Do not automatically merge draft PR #131, change separate GridMates: Sudoku source or delete app data; the user decides when to approve release.
5. The desired player promise remains a comfortable **offline-first illustrated puzzle library**: real volumes, satisfying puzzles, easy nearby play, and “Good puzzles. Good company.”
