**Implementation:** source commit [badb1c1b](https://github.com/PlayerEden/GridMates-Word-Search/commit/badb1c1b735b5616833f3f6a97c73b44aaef9d18). **Status at initial logging:** both exact-source workflows in progress; no new owner APK or on-device approval yet.

## Owner evidence / root cause
Owner supplied a real WS16AZ phone screenshot and corrected the previous color discussion: the red/walnut color is acceptable, while the cabinet is **soft and low-resolution**, with a slightly off-center/rectangular backboard appearance. The WS16AS assembled original had only 602×1120 pixels; the ornate pilasters had just 126px / 120px of source width. The WS16AY ContentScale.Crop could independently crop the backboard and side columns on a tall phone, breaking visual continuity.

## Actual artwork and executable production
- Generated a new detailed illustrated, *empty* walnut-and-gold cabinet master at 1024×1536, with no books, shelves, text, signs or buttons painted into it. Extended the central wood/vine sections vertically using three seamless-blended repetitions of an existing 274px source region (20px overlap), keeping its carved crown/base sharp and proportional. Resulting **1024×2298** portrait image is closer to the actual Android tall-phone ratio and preserves detailed woodgrain while allowing the native UI and shelf/book sprites to remain independent.
- Committed the compact JPEG quality-90 authoring master at `design/visual-system/masters/ws16ba/cabinet_tall_master_q90.jpg`, exact source SHA-256 **d599f7e7510e2b5aaa28fdc20bf33186c5fb245f2ad31922d4e2ad50ffc44bc3**. A JPEG transfer master is a controlled compromise: it contains real, newly generated detail and is never described as lossless against the original full-resolution generated picture. All runtime module exports are lossless PNG crops **of this committed source**.
- `build_ws16ba_hi_res.py` deterministically extracts five independent, reassemblable source-aligned pieces: crown 1024×337, left pilaster 214×1777, backboard 606×1777, right pilaster 204×1777, base 1024×184. Tests reconstruct the committed master pixel-for-pixel and confirm all derived PNG hash values.
- Both `ws01-android-qa.yml` and `ws12g-qa-art-lab.yml` reproduce these five assets in `app/src/debug/assets/ws16ba/shell` before building. `verify_ws16ba_apk.py` checks each actual APK PNG SHA, exact file set and zero unapproved WS16BA image bytes in the release APK.
- `WS16ATModularLibraryScene.kt` prefers the new hi-res art on portrait height≥1.7× width. The five pieces stay independent (backboard behind working shelves/books; pillars/crown/base in front). Their source widths/height ratios closely match the renderer, reducing independent Crop-induced seams. Landscape and missing-new-art cases retain the earlier WS16AS painted fallback.
- Saved Solo/Daily/book catalog, touch logic, native illustrated Library controls and LAN code remain unchanged. QA package remains `com.playereden.gridmates.wordsearch.qa` signed by existing `qa-signing/wordsearch-qa.p12`, and versionCode advances **59→60** for update-in-place. Existing SHA256 signing-certificate guard remains enforced in both Android workflows.
