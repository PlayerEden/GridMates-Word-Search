## What passed in source vs what remains unproven

**Covered by core tests and emulator source/runtime:**
- Host-serialized first valid word claim, duplicate/replayed requests, invalid/out-of-board paths and replay-safe state.
- Verified V2 seeded puzzle fingerprint and monotonic revision validation; host or guest must not create a new Solo result.
- Host guest-reservation/disconnected-present/rejoin state; idle never ends the game by itself.
- Local TCP packet read/write bounds and UI reachability without phones on a network.

**STILL REQUIRES owner physical tests:**
- Two actual phones can discover and join over the same Wi-Fi, with no typed code by default; protected room code flow and manual fallback work.
- Live real-time claim updates appear on both phones without latency, incorrect source colors or repeated claims.
- Rejoin after Wi-Fi interruption and phone background; host must stay open; special cases like guest/private networks and Android 16 local-network restrictions.
- Both devices show same fonts, highlights, 12/15/20 boards and accurate Find/Move gestures with 100–250% zoom and 200% system text.
- Source/QA update compatibility under stable signing has not been proven by a physical in-place update. Keep this as a disposable QA alpha unless established otherwise.

## Development boundaries

- **No chat yet**, no teammate live fingertip/cursor, no internet rooms, and neither Versus mode. Those remain scheduled after this base LAN test.
- The host keeps shared state only while its process and room are alive. This is *not* cloud session persistence.
- Open rooms are for trusted local Wi-Fi. The admission token is saved only on guest device for within-room reconnect; optional PIN rate-limits incorrect attempts.
- B5's separate physical font-spacing approval remains open.
- Keep this branch **draft/unmerged**. Do not claim launch readiness from emulator success. Owner will decide when to begin two-phone testing.
