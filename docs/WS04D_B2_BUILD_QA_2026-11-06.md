## Implementation compared with v0.4.4 screenshots

1. **Zoom geometry:** Removed `size(viewport * zoom)` plus independent `fontScale` which produced letters expanding inside unchanged cells. The complete original `WordGrid` now gets one Compose `graphicsLayer` transform (scaling cells, glyphs, borders, highlighter strokes and layer-inverse hit coordinates uniformly).
2. **Pure mathematics:** New core `BoardViewportTransform` clamps pan by real transformed extent, centers zoom on viewport focus, and provides a reproducible inverse screen-to-cell mapping. JVM tests cover 100/125/145/150/185/200/250%, all bounds and center-preserving zoom.
3. **Compact HUD:** Reduced three tall menu rows to Home/theme+size+challenge/Options and found count/time/Hint. Options holds Customize puzzle, New Puzzle and Feedback settings (with existing user-confirmation on replacement).
4. **Word-list visibility:** Target word list remains a separately scrolling column below board in portrait and alongside it in landscape; smaller chips and `Remaining/Show all` filter expose more targets together with board.
5. **Input mode:** Clearly selected **Find** / **Move** controls on roomy viewports, and explicit `Mode: Find` / `Mode: Move` on narrow landscape. Short landscape has a two-row zoom/mode toolbar.
6. **Layout sizing:** Portrait board takes up to ~54% of available gameplay height, leaving a persistently visible target region. Landscape reserves extra space for the compact toolbar and list.
7. **No content migration:** WordSearch v1 and v2 seeds, target word lists and IDs; Daily and schema4 saves; 12 original Woodland icons; package ID and account independence are unchanged. No new collection, language pack or multiplayer.

## Important limits of current verification

- **CI does NOT execute Android instrumentation tests**; it only compiles their sources. There are no real new Android screenshots or emulator-driven visual assertions from this run. Therefore this is **not yet proof** that Compose's graphics-layer pointer mapping works correctly on actual phones.
- The `BoardViewportTransform` unit tests prove pure pan/zoom math, not Android rendering performance or Touch/Drag semantics.
- 15×15 or 20×20 words that extend beyond a zoomed-in viewport still rely on zoom-out or start/end tap; automatic edge-pan and two-finger pinch zoom remain later options.
- Stable QA debug signing [issue #11](https://github.com/PlayerEden/GridMates-Word-Search/issues/11) is unresolved. Export old Word Search state from Settings **before uninstalling** an APK rejected due to incompatible debug signatures; never uninstall Sudoku.
- New overlays and 200% font/landscape/tall/narrow interactions still need the user's real-device QA. Don't report phone acceptance based on the test suite.
